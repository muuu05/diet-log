# 식단·운동 기록 — 휴대폰 앱 버전

Claude 없이 휴대폰 홈 화면에서 바로 여는 앱(PWA)이에요.

- 기록은 **이 휴대폰 안(IndexedDB)에만** 저장돼요. 서버가 없어서 어디로도 보내지 않아요.
- 한 번 열고 나면 **인터넷이 없어도** 열리고 기록돼요. 사진 읽기만 인터넷이 필요해요.
- 탭: 오늘 · 식단 · 운동 · 몸 · 계획. kg/lb, 인바디, 몸 변화(눈바디·둘레·사진 위치 맞추기·슬라이더 비교), 주간 규칙, 목표 체중·날짜에 맞춘 칼로리·탄단지, 주간 식단, ‘지금 뭐 먹지?’, 비밀번호로 잠그는 백업, 기능별 AI 모델.

## 파일

| 파일 | 역할 |
|---|---|
| `index.html`, `app.css`, `app.js` | 앱 본체 |
| `sw.js` | 오프라인 캐시 (서비스 워커) |
| `manifest.webmanifest`, `*.png` | 홈 화면 이름과 아이콘 |
| `barlow-condensed-*.woff2` | 숫자 글꼴 (라이선스: `OFL-BarlowCondensed.txt`) |

모든 파일이 한 폴더에 평평하게 있어야 해요. 하위 폴더는 없어요.

## 1. 인터넷에 올리기 (GitHub Pages, 무료)

홈 화면 앱은 `https://` 주소가 있어야 설치할 수 있어요. 컴퓨터 브라우저로 하는 게 편해요.

1. github.com에 로그인 → 오른쪽 위 **+** → **New repository**
2. 이름 `diet-log`, **Public** 선택 → **Create repository**
3. 빈 저장소 화면의 **uploading an existing file** 링크 → 이 폴더 안의 파일을 **전부** 끌어다 놓기 → **Commit changes**
4. 저장소의 **Settings** → 왼쪽 **Pages** → **Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 **main** / **(root)** 로 → **Save**
5. 1–2분 뒤 같은 화면 위쪽에 주소가 나와요: `https://<내 아이디>.github.io/diet-log/`

> 무료 계정은 Public 저장소에서만 Pages를 쓸 수 있고, 유료(Pro 등)여도 Pages 사이트 자체는 누구나 열 수 있어요.
> 그래도 괜찮은 이유: 올라가는 건 **빈 앱 코드**뿐이고, 내 기록은 내 휴대폰에만 있어요. 다른 사람이 주소를 열면 자기 휴대폰에 빈 기록이 생길 뿐이에요.

## 2. iPhone 홈 화면에 추가

1. iPhone **Safari**로 위 주소를 열어요.
2. iOS 26 이후: 주소창 옆 **…** → **공유** → **홈 화면에 추가** → 웹 앱으로 여는 옵션을 켠 채로 **추가**
   iOS 18 이하: 아래쪽 **공유** 버튼 → **홈 화면에 추가** → **추가**
3. 이제 홈 화면의 **식단기록** 아이콘으로 여세요.

> ⚠️ Safari 탭과 홈 화면 앱은 저장 공간이 **따로**예요. Safari 탭에서 넣은 기록은 홈 화면 앱에 보이지 않아요.
> 홈 화면 앱을 연 다음부터 기록하세요. (이미 Safari에서 기록했다면 Safari에서 백업 내보내기 → 홈 화면 앱에서 백업 가져오기)

Android(Chrome)는 앱 안에 **앱 설치** 버튼이 나타나거나, Chrome 메뉴의 **홈 화면에 추가**로 설치해요.

## 3. 백업 (꼭 해 두세요)

기록이 휴대폰에만 있어서, 휴대폰을 바꾸거나 홈 화면에서 앱을 지우면 기록이 사라질 수 있어요.

- **계획 탭 → 데이터와 AI → 백업 내보내기**: **비밀번호로 잠그기**가 기본으로 켜져 있어요. 비밀번호(8자 이상)를 두 번 넣고 **잠가서 만들기** → **파일 저장하기**를 누른 뒤, 공유 시트에서 ‘파일에 저장’, iCloud Drive, 카카오톡 나에게 보내기 등으로 보관해요. 잠근 파일 이름은 `…-locked.json`으로 끝나요.
- **백업 가져오기**: 백업 파일을 고르면 지금 기록과 **합쳐요**. 잠긴 파일이면 비밀번호부터 물어봐요. 같은 날짜 항목은 백업 내용으로 바뀌고, 나머지는 그대로 남아요. 잠그지 않은 예전 백업도 그대로 가져올 수 있어요.
- 잠금 방식: 비밀번호를 PBKDF2-HMAC-SHA256으로 60만 번 늘려(OWASP 권장치) AES-256-GCM 키를 만들고, 기록을 gzip으로 줄인 뒤 암호화해요. 파일에서 읽을 수 있는 건 솔트·IV·설정값뿐이고, 파일이 한 글자라도 바뀌면 열리지 않아요. 휴대폰 브라우저에 들어 있는 Web Crypto로 처리해서 외부 라이브러리는 없어요.
- 비밀번호는 어디에도 저장하지 않아요. **잊으면 누구도 열 수 없어요.** ‘월수금은 한강을 달린다’처럼 문장으로 정해 두면 기억하기 쉬워요.
- 일요일(휴식일)에 백업할 때가 되면 앱이 알려 줘요.

## 4. AI 기능 (선택)

식사 사진 칼로리 추정, 인바디 결과지 읽기, NRC 러닝 캡처 읽기, 주간 식단 만들기, ‘지금 뭐 먹지?’의 새 레시피는 **내 Anthropic API 키**로 Claude를 불러서 해요. 키가 없어도 나머지는 전부 돼요. 직접 입력할 때 사진을 붙여 둘 수도 있어요.

1. [Claude Console](https://platform.claude.com)에서 계정을 만들고 크레딧을 충전한 뒤 API 키를 만들어요.
2. 앱의 **계획 탭 → 데이터와 AI**에 키를 붙여 넣고 **저장** → **연결 확인**
3. 모델: 기본 **Sonnet 5.5**, 가장 꼼꼼한 **Opus 5.5**(요금 2배), 가장 싼 **Haiku 5.5**
4. **기능별 모델 (선택)**: 사진 읽기(식사·러닝·인바디), 주간 식단 만들기, ‘지금 뭐 먹지?’ 새 레시피마다 모델을 따로 고를 수 있어요. 고르지 않은 기능은 3번의 기본 모델을 따라요. 고르는 동안 아래에 그 조합의 한 달 예상 금액이 바로 나와요(아래 사용량 기준. 예: 사진 Haiku · 식단 Opus · 새 레시피 Sonnet이면 약 $1.14, 전부 Sonnet이면 약 $1.67). 더 싼 모델로 바꿨다면 처음 몇 번은 결과를 직접 확인해 보세요.
5. **연결 확인**은 쓰는 모델마다 짧은 요청을 한 번씩 보내서, 이 키로 쓸 수 없는 모델이 있으면 바로 알려 줘요.

비용은 Claude 구독(Pro 등)과 **별개**로, 쓴 만큼 Console에서 나가요. 청구 주소에 따라 세금이 더해질 수 있어요.
2026년 11월 기준 공시 가격은 100만 토큰당 Opus 5.5 입력 $4 / 출력 $20, Sonnet 5.5 $2 / $10, Haiku 5.5 $0.10 / $0.50이에요.

- 5.x 모델은 답하기 전에 스스로 생각(adaptive thinking)하고, 그 생각도 출력 토큰으로 계산돼요. 그래서 앱은 사진 읽기와 새 레시피에는 effort `low`, 주간 식단에는 `medium`을 요청하고, 생각할 자리를 남기려고 최대 출력을 사진·새 레시피 4,000토큰, 식단 16,000토큰으로 잡아요.
- 추정치(직접 계산): 사진 한 장은 입력 약 2,700토큰(사진 약 2,350 + 지시문), 출력 수백 토큰이라 **Sonnet 약 1센트, Opus 약 2센트**예요. 주간 식단은 **Sonnet 약 8센트, Opus 약 17센트**예요.
- ‘지금 뭐 먹지?’ 새 레시피 한 번은 입력 약 500토큰, 출력(생각 포함) 약 300–1,400토큰으로 잡으면 **Sonnet 약 1센트 안팎, Opus 약 1–3센트**예요. 이번 주 식단에서 골라 주는 건 무료예요.
- 한 달 예상(하루 사진 3장, 주 3번 러닝 캡처, 인바디 1번, 식단 5번): **Sonnet 약 $1.4, Opus 약 $2.9**. 하루 사진 1장이면 그 절반 이하, 5장이면 2배쯤이에요. 새 레시피를 하루 1번 받으면 Sonnet 약 $0.1–0.5, Opus 약 $0.25–0.9가 더해져요.
- 실제로 쓴 양은 앱의 **데이터와 AI**에 이번 달 요청 수, 토큰 수, 예상 금액으로 나와요(이 휴대폰에서 쓴 것만). 정확한 금액은 Console에서 확인하세요.

안전하게 쓰는 법:
- 이 앱 전용 키를 따로 만들고, Console의 결제 설정에서 **월 사용 한도**를 걸어 두세요.
- 키는 이 휴대폰에만 저장되고 `api.anthropic.com`으로만 보내져요. 휴대폰을 남에게 빌려줄 땐 ‘키 지우기’를 눌러도 돼요.

## 5. 식단 탭: 하루 목표와 주간 식단

**하루 목표** (API 키 없이 돼요)
1. **정보 입력**에서 성별, 나이, 키, 활동량, 목표 체중, 목표 날짜, 체형 목표, 감량 속도를 넣어요. 체중은 아침 체중 추세를 써요.
2. 감량 속도를 **목표 날짜에 맞추기**로 두면 남은 kg ÷ 남은 주로 한 주 속도를 정해요. 주 체중의 1%(최대 1 kg)보다 빠르게는 잡지 않고, 그럴 땐 경고와 함께 그 속도로 도달하는 날을 보여 줘요. 목표 체중에 닿으면 유지 칼로리로 바꿔요. 위쪽 막대는 첫 체중 → 지금 → 목표까지 얼마나 왔는지예요.
3. 계산: 기초대사량(Mifflin-St Jeor 공식, 최근 8주 안의 인바디가 있으면 그 값) × 활동량 − 감량분(1 kg ≈ 7,700 kcal).
   남성 1,500 kcal, 여성 1,200 kcal 밑으로는 내리지 않아요.
4. 단백질은 체중 1 kg당 1.6–2.2 g(목표 체중이 더 낮으면 목표 체중 기준), 지방은 칼로리의 20–30%, 나머지가 탄수화물이에요.
5. 체형 목표(린 · 리컴프 · 하이브리드 · V자 상체 · 허리 둘레)는 칼로리 계산을 바꾸지 않아요. 한 부위만 골라 빼는 방법은 없어서, 식단 구성과 조언에만 쓰여요. **하이브리드**(근력과 러닝 체력 같이)를 고르면 탄수화물이 체중 1 kg당 몇 g인지를 하루 1시간쯤 운동하는 사람의 권장량(5–7 g)과 비교해 보여 주고, 모자라면 러닝 전 끼니와 운동 전후로 몰아 먹게 안내해요.
6. **이 목표 적용**을 누르면 오늘 탭과 식단이 이 숫자를 따라요.
7. 식사를 14일 중 10일 이상 기록하고 체중 추세가 쌓이면 **기록으로 계산**을 쓸 수 있어요. 평균 섭취량과 실제 체중 변화로 유지 칼로리를 거꾸로 구해요.

**지금 뭐 먹지?** (오늘 탭)
- 지금 시간으로 끼니를 정해요: 10:30 전 아침, 14:30 전 점심, 17:30 전 간식, 그 뒤 저녁. 이번 끼니 목표는 하루 목표의 아침 25%, 점심 35%, 간식 12%이고, 저녁은 오늘 남은 전부예요. 단백질은 최소 25 g(간식 15 g)으로 잡아요.
- **이번 주 식단 레시피 중에서** 그 목표에 맞는 양(0.5–1.5인분)으로 3가지를 골라 줘요. API 키 없이 돼요. 칼로리는 넘치는 쪽을 모자란 쪽보다 더 피하고, 단백질이 모자란 것도 따져요.
- **Claude에게 새 레시피 받기**(API 키 필요): 이번 끼니 목표, 오늘 운동 종류, 체형 목표, 빼야 할 음식을 보내서 레시피 하나를 새로 받아요. 기록이나 사진은 보내지 않아요. **다른 레시피 받기**를 누르면 앞서 받은 건 빼고 다시 받아요.
- **먹었어요**를 누르면 그 양 그대로 지금 시간에 기록되고, 식사 목록에 ‘추천대로 기록’으로 보여요.

**주간 식단** (API 키 필요)
- **식단 만들기**: 목표, 운동 요일, 빼야 할 음식, 요리 방식을 Claude에 보내서 월–일 식단과 레시피를 받아요. 기록이나 사진은 보내지 않아요.
- 영양값은 재료 양으로 계산한 추정치예요. 칼로리가 단백질·탄수화물·지방(4/4/9 kcal)과 12% 넘게 안 맞으면 앱이 다시 계산해요.
- 하루 목표가 바뀌면 집밥 양(인분)을 0.7–1.3배 안에서 자동으로 맞춰요. 식단을 다시 만들 필요가 없어요.
- **먹었어요**를 누르면 그 양 그대로 식사에 기록돼요. 장보기 목록은 일주일 치를 합쳐 보여 주고, 체크한 건 휴대폰에 남아요.
- 비용: 출력(생각 포함)을 최대 16,000토큰으로 묶어 둬서 한 번에 최대 Sonnet 약 $0.16, Opus 약 $0.32예요. 보통은 그 절반 아래로 예상돼요. 실제 쓴 토큰 수는 식단 아래에 나와요.

## 6. 몸 변화 (눈바디·둘레)

- **몸 탭 → 몸 변화 → 기록하기**: 정면·측면·후면 사진과 허리·엉덩이·가슴·팔·허벅지 둘레(cm)를 날짜별로 남겨요.
- **사진 위치 맞추기**: 같은 자세의 지난 사진이 있으면, 새 사진을 고른 뒤 지난 사진이 흐리게 겹쳐 보여요. 크기·좌우·위아래를 움직여 어깨·허리·발 위치를 맞추고 **맞춤 완료**를 누르면 3:4(810×1080)로 잘라 저장해요. 그대로 두려면 **그대로 쓰기**. 둘 중 하나를 고르기 전엔 저장되지 않아요.
- **사진 비교**: 사진이 두 번 이상 쌓이면 처음과 최근 사진을 보여 주고, 눌러서 자세와 날짜를 골라요. 기본은 **슬라이더**(막대를 밀어 이전·이후 사진을 겹쳐 봐요)이고 **나란히**로 바꿀 수 있어요. 허리 둘레는 그래프로 보여요.
- **기록 알림**: 마지막 기록 뒤 2주가 지난 일요일에 오늘 탭에 ‘몸 변화 기록할 날이에요’ 카드가 떠요(×를 누르면 그날은 닫혀요). 몸 탭에는 다음 기록 추천일이 나와요.
- 사진은 **이 휴대폰에만** 저장되고 어디로도 보내지 않아요(AI에도 보내지 않아요). 다만 **백업 파일에는 사진도 들어가요.** 백업을 내보낼 때 비밀번호로 잠가 두세요.
- 사진은 긴 변 1080px로 줄여서 저장해요. 2주에 한 번 세 장씩이면 1년에 수십 MB 정도로 추정되고, 백업 파일도 그만큼 커져요.

## 7. 고치고 다시 올릴 때

1. 바뀐 파일을 GitHub 저장소에 다시 올려요 (같은 이름이면 덮어써요).
2. **`sw.js` 맨 위의 `VERSION`을 올려요** (예: `"v1"` → `"v2"`). 이걸 안 하면 휴대폰이 예전 파일을 계속 써요.
3. 앱은 열 때와 다시 돌아올 때(30분에 한 번까지) 새 버전을 확인해요. 준비되면 위쪽에 ‘새 버전이 준비됐어요’ 띠가 뜨고, **지금 적용**을 누르거나 다른 앱에 갔다 오면 바뀌어요. 기록은 그대로예요.

## 보안 메모

- `index.html`의 콘텐츠 보안 정책(CSP)이 이 사이트 파일과 `api.anthropic.com` 말고는 아무것도 불러오지 못하게 막아요. 외부 글꼴·분석 도구·광고 없음.
- 화면에 글자를 넣을 때 HTML로 해석하지 않아서(`textContent`), 사진 읽기 결과나 백업 파일 안의 글자가 코드로 실행되지 않아요.
- 앱 잠금(PIN)은 따로 없어요. 휴대폰 잠금이 앱 기록도 지켜 주고, 밖으로 나갈 수 있는 건 사진까지 들어 있는 **백업 파일**이라서 백업을 **비밀번호로 잠가 두는 것**이 더 중요해요.
